# Repository Guidelines

## Project Overview

`my-better-t-app` is a Bun + Turborepo monorepo generated by Better-T-Stack. It is a full-stack TypeScript starter with email/password authentication; the current API surface is a public `healthCheck` and a protected `privateData` query. There are no application domain tables yet—only Better Auth tables.

- **Web** (`apps/web`): TanStack Start + TanStack Router, React 19, Vite 8, Tailwind CSS v4.
- **Native** (`apps/native`): Expo Router + React Native, styled with Unistyles.
- **Server** (`apps/server`): Hono on Cloudflare Workers, exposing Better Auth and tRPC.
- **Shared packages**: tRPC router (`packages/api`), Better Auth (`packages/auth`), Drizzle + Neon (`packages/db`), shadcn/Base UI primitives (`packages/ui`), Alchemy/Cloudflare deployment (`packages/infra`).

## Architecture & Data Flow

```text
web/native -> tRPC client -> Hono /trpc/* -> createContext(db, session) -> procedure -> JSON
                     \-> /api/auth/* -> Better Auth -> Drizzle -> Postgres (Neon HTTP)
```

- **Server entry** (`apps/server/src/index.ts`): `new Hono()` with middleware order `logger()` → CORS on `/*` (single `CORS_ORIGIN`, `credentials: true`) → Better Auth on `/api/auth/*` → `trpcServer` on `/trpc/*` → `GET /` returning `"OK"`. `export default app` is the Worker fetch handler.
- **Per-request context** (`apps/server/src/context.ts`): `getDb()` creates a Neon HTTP client, then `createAuth(db).api.getSession({ headers })`; procedures receive `{ db, session }`. No module-level DB or auth singletons.
- **tRPC core** (`packages/api/src/index.ts`): `initTRPC.context<Context>().create()` with no transformer/superjson and no custom error formatter. `protectedProcedure` throws `UNAUTHORIZED` when `ctx.session` is null and narrows `session` to non-null. The router is in `packages/api/src/routers/index.ts`; clients import `AppRouter` type-only.
- **Web client** (`apps/web/src/router.tsx`): creates a `QueryClient` (60s `staleTime`, global `QueryCache.onError` → toast with retry), a module-level `httpBatchLink` client to `${VITE_SERVER_URL}/trpc` with `credentials: "include"`, and a `createTRPCOptionsProxy`. `getRouter()` supplies `{ trpc, queryClient }` as router context and wraps routes in `TRPCProvider`.
- **Web routing/auth**: TanStack Router file routes under `apps/web/src/routes`. The pathless `_auth` layout is `ssr: false`; `beforeLoad` calls `authClient.getSession()` and redirects to `/login` when absent. Client auth comes from `better-auth/react` (`apps/web/src/lib/auth-client.ts`).
- **Native client** (`apps/native/utils/trpc.ts`): module-level `QueryClient` + `createTRPCOptionsProxy`, consumed directly with `useQuery(trpc.x.queryOptions())`. Native requests use `credentials: "omit"` and manually forward `authClient.getCookie()` in a `Cookie` header; web uses `credentials: "include"`. Changing one side without the other causes 401s.
- **Auth config** (`packages/auth/src/index.ts`): factory `createAuth(env, database, desktopOrigins?)` using the Drizzle adapter from `@better-auth/drizzle-adapter/relations-v2`, the Expo plugin, email/password enabled, trusted origins, and cookies `SameSite=None; Secure; HttpOnly`.
- **Data layer** (`packages/db/src/index.ts`): `createDb(env)` → `neon(DATABASE_URL)` + `drizzle({ client, relations })` via `drizzle-orm/neon-http`. The runtime expects a Neon-compatible HTTP connection; a plain local Postgres URL is not a drop-in replacement at runtime.
- **Deployment** (`packages/infra/alchemy.run.ts`): one Alchemy stack creates the Cloudflare Worker (`server`, port 3000) and the Cloudflare Vite website (`web`, port 3001), injecting `BETTER_AUTH_URL` and `VITE_SERVER_URL`.

## Development Commands

Run commands from the repository root unless noted. `bun install` runs `postinstall`, which executes `varlock codegen` for web, server, native, and db.

```bash
bun install
# Create ignored env files before first run:
#   apps/server/.env   BETTER_AUTH_SECRET (>=32 chars), BETTER_AUTH_URL, CORS_ORIGIN, DATABASE_URL
#   apps/web/.env      VITE_SERVER_URL
#   apps/native/.env   EXPO_PUBLIC_SERVER_URL
bun run db:push
bun run dev
```

| Command | Effect |
| --- | --- |
| `bun run dev` | Runs Turbo `dev`: Expo (`native#dev`) plus Alchemy (`infra#dev`), which serves the API on `:3000` and web on `:3001`. |
| `bun run dev:native` | Starts only the Expo dev server (`turbo run dev -F native`). |
| `bun run build` | Builds web (`vite build`) and server (`tsdown`); native is not built. |
| `bun run check-types` | `turbo run check-types`; web runs `vite build && tsc --noEmit`, others run `tsc --noEmit`. |
| `bun test` | Not wired: exits 1 with `0 test files matching ...`; no package defines a `test` script. |
| `bun run check` | `ultracite check` (Biome lint/format check). |
| `bun run fix` | `ultracite fix`; applies formatting/lint fixes. |
| `bun run db:push` | `drizzle-kit push` for the schema. |
| `bun run db:generate` | Generates SQL migrations into `packages/db/src/migrations`. |
| `bun run db:migrate` | Applies generated migrations. |
| `bun run db:studio` | Opens Drizzle Studio. |
| `bun run env:generate` | Regenerates Varlock TypeScript env files; does not include `packages/infra`. |
| `bun run deploy` / `bun run destroy` | Alchemy deploy/destroy for the Cloudflare stack. |
| `cd packages/infra && bunx alchemy profile edit` | First-time Alchemy/Cloudflare provider setup. |
| `cd apps/web && bunx vite dev` | Web-only dev server on port 3001, bypassing Turbo. |
| `cd apps/native && bun run ios` / `bun run android` | Local native builds via Expo. |

**Known broken scripts in the current repo state** (do not rely on the README here):

```bash
bun run dev:web    # turbo: Could not find task `dev:bare` in project
bun run dev:server # turbo: No package found with name 'hono' in workspace
```

- `dev:bare` exists in `apps/web/package.json` but is not registered in `turbo.json`, so Turbo 2 refuses it. Use `cd apps/web && bunx vite dev` or add a `dev:bare` task to `turbo.json`.
- `dev:server` filters `-F hono`, but the server package is named `server` and has no `dev`/`dev:bare` script. Use `bun run dev` (Alchemy serves the Worker) or add a server dev script plus a corrected filter.
- Do not run a web-only server alongside `bun run dev`; both bind port 3001.
- `CORS_ORIGIN` is required by both `apps/server/.env.schema` and `packages/infra/alchemy.run.ts`. Set a valid value before deploying, then replace it with the exact deployed web origin and redeploy.
- On a physical device, `EXPO_PUBLIC_SERVER_URL=http://localhost:3000` points at the device itself; use the host machine's LAN IP or a tunnel.

## Code Conventions & Common Patterns

- **Formatting/linting**: Biome via Ultracite only (`biome.jsonc` extends `ultracite/biome/{core,react,tanstack}`); no ESLint, Prettier, or per-package configs. Use `bun run fix` and `bun run check`; 2-space indentation, double quotes, semicolons, kebab-case filenames.
- **Naming**: kebab-case files (`sign-in-form.tsx`, `message-scroller.tsx`), camelCase symbols, packages named `@my-better-t-app/<name>`, DB snake_case columns mapped to camelCase properties.
- **Workspace imports**: internal packages export raw TypeScript (`"exports": { ".": "./src/index.ts", "./*": "./src/*.ts" }`) and have no build step. Import deep subpaths, e.g. `@my-better-t-app/ui/components/button` and `@my-better-t-app/api/routers/index`. `packages/ui` has no root export, so do not import it as a barrel.
- **Type-only boundaries**: clients import `import type { AppRouter } from "@my-better-t-app/api/routers/index"` so server code is not bundled. Use `import type` for types (`verbatimModuleSyntax` is on in the shared/base configs).
- **Path aliases**: `@/*` is app-local and resolves differently: `apps/web/src`, `apps/server/src`, and the native app root. `@my-better-t-app/ui/*` also resolves through web tsconfig/Vite paths. Do not assume the root `tsconfig.json` provides aliases.
- **Adding tRPC procedures**: define them in `packages/api/src/routers/index.ts` (or compose a new router into `appRouter`) with `publicProcedure` or `protectedProcedure`. Use Zod v4 for inputs (`z.email()`, not the Zod 3 `z.string().email()` pattern). No transformer is configured, so `Date` values arrive as strings on clients.
- **Dependency injection**: server code uses factories—`createDb(env)`, `createAuth(env, db)`, `createContext(...)`—and passes config in. Keep it that way; do not introduce module-level DB/auth singletons.
- **Data fetching/state**: TanStack Query is the only client state layer (no Redux/Zustand). Web uses `useTRPC()` + `trpc.x.queryOptions()`; native uses the singleton proxy. Invalidate or refetch queries after auth mutations.
- **Forms**: TanStack Form with Zod `validators.onSubmit`, render-prop `form.Field`, and `form.Subscribe` for submit state; call the Better Auth client, then navigate (web) or invalidate queries (native).
- **Auth guards**: server-side `protectedProcedure`; web `_auth` route `beforeLoad`; native conditional rendering (no route guard).
- **Shared UI**: primitives live in `packages/ui` and use **Base UI**, not Radix. Use Base UI's `render` prop (e.g. `render={<Button />}`), not `asChild`. Components use `data-slot`, `cva`, and `cn`; import as `@my-better-t-app/ui/components/<name>`. Add shared primitives with `npx shadcn@latest add <name> -c packages/ui`; app-specific blocks from `apps/web`.
- **Styling**: web is Tailwind v4 CSS-first—no `tailwind.config.*`. Tokens and `@source` globs live in `packages/ui/src/styles/globals.css`; add a new `@source` for new top-level source directories. Native uses Unistyles: register themes/breakpoints in `apps/native/unistyles.ts`, use tokens from `apps/native/theme.ts`, and `StyleSheet.create(theme => ...)`.
- **Env access**: `.env.schema` is the contract. Varlock generates gitignored `src/env.ts` files (do not edit). Server code reads Cloudflare bindings via `ENV` from `cloudflare:workers` (`apps/server/src/env.server.ts`); web reads `import.meta.env` through `apps/web/src/env.public.ts`; native imports generated `ENV`. After adding a variable, update `turbo.json` `globalEnv` so caches invalidate.
- **DB changes**: edit `packages/db/src/schema/*`, update `relations.ts` if needed, then run `bun run db:generate` and `bun run db:migrate` (or `db:push` for local iteration). `DATABASE_URL` is sourced from `apps/server` through Varlock, not from a `packages/db/.env`.
- **Error handling**: throw `TRPCError` for API failures; Better Auth errors surface as `error.error.message` in form callbacks; web has a global QueryCache toast with a retry action. Native has no global query error UI.

Example procedure shape:

```ts
// packages/api/src/routers/index.ts
import { z } from "zod";
import { protectedProcedure, router } from "../index";

export const appRouter = router({
  // ...existing healthCheck / privateData
  myQuery: protectedProcedure
    .input(z.object({ id: z.string() }))
    .query(({ ctx, input }) => ({
      id: input.id,
      userId: ctx.session.user.id,
    })),
});
```

## Runtime/Tooling Preferences

- **Runtime**: Bun only, pinned to `bun@1.4.2` in root `package.json`. No Node `engines` field is declared; use `bun run`/`bunx`, and do not introduce npm/pnpm/yarn lockfiles.
- **Monorepo**: Turbo 2.11 (`turbo.json`, `ui: "tui"`). Turbo 2 only runs tasks registered in `turbo.json`; adding a package script alone is not enough. Register new tasks (e.g. `test`) there and use `-F <package-name>` filters, not directory names.
- **TypeScript**: `typescript@^6.0.3`. Packages/server inherit `packages/config/tsconfig.base.json` (strict, `noUncheckedIndexedAccess`, `noUnusedLocals/Parameters`, bundler resolution, Node + Cloudflare Worker types). `apps/web` and `apps/native` use their own TS baselines, so shared-base changes do not affect them.
- **Frameworks**: Hono 4, tRPC 11 + TanStack Query 5, Better Auth 1.7.7 (+ Expo plugin), Drizzle ORM/Kit 1.0.0-rc.4 on Neon HTTP, Tailwind v4, TanStack Start/Router, Expo 58 / React Native 0.88 / React 19.3 with Unistyles and React Compiler.
- **Env/tooling**: Varlock 1.18 owns env loading and codegen. Bun's automatic `.env` loading is disabled (`env = false`), so scripts relying on `process.env` need Varlock (`varlock/auto-load`) or explicit values. `env:generate` creates types only, not runtime values.
- **Deployment**: Alchemy 2 beta (`alchemy dev/deploy/destroy`) targeting Cloudflare Workers (`nodejs_compat`). No Wrangler config or Docker setup is committed. No `eas.json` or store-submission config exists; native builds use `expo run:ios|android`.
- **Native configs are CommonJS**: `apps/native` has no `"type": "module"`; keep `babel.config.js` and `metro.config.js` in CJS and preserve the Varlock Metro/Babel wrappers plus the `.alchemy` blocklist.
- **No Tailwind JS config**: Tailwind v4 is configured in CSS (`packages/ui/src/styles/globals.css`); do not add `tailwind.config.*`.
- **Skills**: `.omp/skills/<name>/SKILL.md` mirrors `skills-lock.json`. If a matching skill exists, read it before implementing framework-specific work.

## Library Documentation (ctx7)

Use the `ctx7` CLI to fetch current documentation whenever the user asks about a library, framework, SDK, API, CLI tool, or cloud service—even well-known ones like React, Next.js, Prisma, Express, Tailwind, Django, or Spring Boot. This includes API syntax, configuration, version migration, porting code between libraries/platforms/SQL dialects, library-specific debugging, setup instructions, and CLI tool usage. Use it even when you think you know the answer; training data may be stale. Prefer it over web search for library docs.

Do not use ctx7 for refactoring, debugging, or reviewing code that does not depend on a library/platform API, or for general programming concepts.

1. Resolve the library: `npx ctx7@latest library <name> "<what to look up>"`. Use the official name with proper punctuation (e.g. "Next.js", not "nextjs"; "Customer.io", not "customerio"; "Three.js", not "threejs"). You MUST run `library` first to get a valid ID unless the user provides one directly in `/org/project` format.
2. Pick the best match (ID format `/org/project`) by exact name, description relevance, code snippet count, source reputation (High/Medium preferred), and benchmark score (higher is better). If results look wrong, retry with alternate names or a rephrased query.
3. Fetch docs: `npx ctx7@latest docs <libraryId> "<what to look up>"`. Run a separate `docs` command per distinct concept unless the question is about how concepts interact. Keep each query specific and single-concept; combined multi-topic queries dilute ranking and return shallow results.
4. Answer using the fetched documentation. For version-specific docs, use `/org/project/version` from the `library` output (e.g. `/vercel/next.js/v16.2.9`).
5. Do not run more than 3 commands per question, and never include API keys, passwords, or credentials in queries.
6. If a command fails with a quota error, inform the user and suggest `npx ctx7@latest login` or setting `CONTEXT7_API_KEY` for higher limits. Do not silently fall back to training data.

## Testing & QA

- **There are no tests.** No `*.test.*`/`*.spec.*` files, no test runner (`vitest`, `jest`, `playwright`, `cypress`), no `@types/bun`, no `test` script, and no test config. `bun test` exits 1 with `0 test files matching ...`. `apps/web` declares `@testing-library/*` and `jsdom`, but nothing uses them.
- **No CI or git hooks.** There is no `.github/` directory and no husky/lefthook/lint-staged setup; checks are manual.
- **Available quality gates**:
  - `bun run check` — Ultracite/Biome lint + format check.
  - `bun run fix` — apply Biome fixes.
  - `bun run check-types` — Turbo typecheck; web builds first to generate `routeTree.gen.ts`.
  - `bun run build` — verify web and server production builds.
  - `bun run env:generate` — required after `.env.schema` changes before typechecking.
- **Testing if you add it**: use `bun:test` (zero-install, TS-native) and colocate `*.test.ts`/`*.test.tsx` beside the code. Add `"test": "bun test"` to the package and a `test` task to `turbo.json`; add `@types/bun` (and `"bun"` to `types`) or exclude tests from `tsc` because the shared base only includes `node` and Cloudflare Worker types.
- **Useful test seams**: `appRouter.createCaller({ session: null, db })` for procedure tests (`healthCheck` is public; `privateData` throws `UNAUTHORIZED` without a session); `createAuth(env, db)` and `createDb(env)` are injectable factories. Importing `apps/server/src/*` under Bun requires mocking `cloudflare:workers`. Web modules are Vite-coupled (`import.meta.env`, CSS `?url`), so DOM component tests need Vitest or a Bun `[test] preload` with happy-dom; the existing `jsdom` + RTL deps are not wired up.
- **Coverage**: no coverage runner, config, or threshold exists. Do not claim or invent coverage expectations.
